Data Flow & Architecture

How NorthStar is built, how data moves through it, and what it represents when synthetic generation is replaced by production systems. Each diagram answers one question. Real marketing, web, CRM, leasing, and property-management systems each produce a fragment of the resident journey; NorthStar integrates those fragments, resolves their shared keys, publishes them into a governed model, and turns them into operational and executive decisions.

01  NorthStar Platform Architecture

What is NorthStar made of? The platform runs as a single vertical pipeline. Between staged files in blob storage and the SQL warehouse, the Operations Pipeline Report validates, reconciles, and controls what gets published. The semantic model then serves the two analytical experiences. The Metadata Portal documents every layer without participating in the flow.

Operations Pipeline Report controls the publish into the warehouse. Metadata Portal documents the platform.

02  NorthStar Data Processing Flow

How does data move? The generator creates canonical truth first, then domain pipelines process CRM, marketing funnel, and property operations. Their results are reconciled against that truth, published as CSV to blob, loaded into the warehouse, and the semantic model refreshes. The Operations Pipeline Report observes the reconciliation, publish, and load stages.

Canonical truth first, then domain pipelines, reconciliation, and publish.

04  Prospect-to-Resident Narrative

How does one resident move through the business, and which system records each event? A website visit is not a leasing tour; an application is not a signed lease; a signed lease is not a move-in. These distinctions are the narrative.
