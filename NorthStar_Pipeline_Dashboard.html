Pipeline Dashboard

A user manual for the NorthStar operations dashboard: the interface an operator uses to see whether the pipeline is healthy, investigate what failed, and clear reconciliation work. Served by the /api/dashboard endpoint as a self-contained HTML page.

Anatomy of the interface

Every tab renders inside the same page frame. The banner and tab bar are constant; the body below the tab bar changes per tab. The diagram shows the fixed regions an operator sees on load.

Alert banner

Produced by _render_alert_banner(), which calls _check_alerts() on every page load. If no condition is met, no banner renders, so a quiet banner means a quiet system. Each alert links to the tab and filter that isolates it.

CheckConditionLinks to
Pipeline failuresRuns with Status = 'FAILED' in the last 24 hours.tab=runs&status=FAILED&range=7d
High-severity actionsSeverity = 'high' AND Status = 'OPEN' in reconciliation_actions.tab=reconciliation&severity=high&rstatus=OPEN
Bronze coverage gapMissing bronze coverage in the last 7 days.tab=runs&pipeline=bronze&range=7d

Overview

The morning health check
Querytab=overview
Purpose

The morning glance. Confirms at a glance whether last night's loads were normal before any detail is opened.

Questions it answers
  • Did last night run?
  • Did it load about the volume it should have?
  • Is there reconciliation work waiting?
What it shows

KPI cards (Open actions, Coverage gap) and a rows-loaded trend chart showing load volume over time.

When an operator uses it

First thing, every day. If the cards and trend look normal and the banner is quiet, no further tab is needed.

Run history

Investigating pipeline executions
Querytab=runs
Purpose

The investigation surface. Lists individual pipeline runs so a failure or an abnormal load can be traced to a specific run.

Questions it answers
  • Which run failed, and when?
  • How long did a run take?
  • How many rows did a given run move?
What it shows

A table of runs with pipeline, date, status badge, duration, and row counts. Filterable by pipeline, status, and date range.

When an operator uses it

When the banner reports a failure, or when the Overview trend shows an abnormal day worth explaining.

Reconciliation

Resolving data-quality actions
Querytab=reconciliation
Purpose

The work queue. Surfaces reconciliation actions the pipeline raised for a human to triage, so divergences are resolved rather than ignored.

Questions it answers
  • What discrepancies were detected?
  • Which are high-severity and still open?
  • Which have already been handled?
What it shows

A table of actions with severity and status badges. Supports bulk acknowledgment and CSV export of the current filtered list.

When an operator uses it

Daily triage, and immediately when the banner flags open high-severity actions.

Attribution gap

Watching the integrity of attribution
Querytab=attribution
Purpose

The integrity watch. Monitors the gap between signed leases and leases tied back to a marketing journey, so a widening gap cannot hide in the totals.

Questions it answers
  • Is the unattributed-lease gap stable?
  • Is it widening over time?
  • Did it jump on a particular date?
What it shows

A trend of the unattributed-lease gap over time, monitored on its own rather than blended into aggregate metrics.

When an operator uses it

Periodically, and whenever attribution figures look lower than expected on the analytics side.

Activity log

The audit trail of record
Querytab=activity
Purpose

The record of record. A chronological audit trail of pipeline events, kept so any number can be explained after the fact.

Questions it answers
  • What happened, in what order?
  • When did a specific event occur?
  • What is the evidence behind a reported number?
What it shows

A time-ordered list of pipeline events, the raw audit trail beneath the summarized tabs.

When an operator uses it

When a number has to be defended or an incident reconstructed after it has passed.

Filters

Run history and Reconciliation accept query-string filters. Omitted or unrecognized parameters fall back to defaults.
