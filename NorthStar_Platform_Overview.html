Platform Overview

A single-page map of NorthStar: what it is, how the pieces fit together, and where to go next for detail.

What NorthStar Is

NorthStar is a self-contained analytics platform built around a synthetic multifamily housing portfolio. It generates its own data, models that data in a dimensional warehouse, centralizes business logic in a semantic layer, and delivers results through several analytical applications. Each layer is documented in this portal.

The data is synthetic. The portfolio, pipelines, semantic model, and reporting reproduce the structure of a production marketing-analytics environment, including its dependencies, constraints, and data-quality conditions.

Architecture

NorthStar has four layers: data creation, data engineering, business intelligence, and applications. The applications consume different sources. The Executive Dashboard and Attribution Lab read business data from the semantic model. The Pipeline Operations Dashboard reads pipeline telemetry from the engineering layer. The Metadata Portal documents the platform.

The logical architecture describes these layers. The physical architecture describes the Azure implementation.

Data Flow

The primary path runs from generation to reporting. The SQL Loader branches to two destinations: business data to Azure SQL Database, and pipeline telemetry to the Pipeline Operations Dashboard. The Data Flow and Architecture page documents each step.

Python Generator → Parquet Files → Azure Blob → Azure Functions → SQL Loader → Azure SQL Database → Power BI Semantic Model → Executive Dashboard, Attribution Lab

Four reconstruction pipelines rebuild the same facts from raw vendor files. A reconciliation step measures the divergence between each reconstruction and canonical truth. This dual-source design produces a measured value for pipeline accuracy.

The four composite indexes are Geographic (GPI), Operations (OPI), Vendor (VPI), and Portfolio Health (PHI). They form the analytical center of the platform. The Executive Index Framework documents how each index is constructed and the decision it supports.

Development Philosophy

Business logic has one home

Definitions are created once, validated once, and reused across applications rather than rewritten per report.

Data quality is an operating process

Quality is maintained through validation, ownership, and monitoring, not a one-time cleanup.

A visual answers a question

Every KPI exists to support a decision, not because the data happens to be available.

Documentation is part of the system

A platform is incomplete when its logic cannot be traced or maintained by someone other than its author.

Architecture supports change

New measures, applications, and data sources can be added without rebuilding the system.
